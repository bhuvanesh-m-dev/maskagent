MaskAgent

On-Device AI Browser Agent for Privacy-Preserving Web Automation

See the page. Protect the data. Let AI act.

MaskAgent is a privacy-focused browser extension that combines on-device privacy protection, DOM/UI understanding, and local AI-powered browser automation.

Instead of blindly sending a webpage containing personal information to an AI model, MaskAgent first identifies sensitive information such as names, email addresses, phone numbers, addresses, passwords, and other personally identifiable information.

The sensitive content is then masked/redacted before AI processing.

MaskAgent can then use a local AI model through Ollama to understand the sanitized webpage and determine browser actions.

Features

Privacy-Preserving AI Processing

MaskAgent identifies potentially sensitive UI elements and masks them before AI processing. Examples include: Names, Email addresses, Phone numbers, Passwords, Addresses, Dates of birth, and other personally identifiable information.

DOM + Visual Understanding

MaskAgent can work with webpage structure and visual context to understand the current page. The extension can identify: Text fields, Buttons, Form elements, Labels, Links, Page structure, and Visible UI elements.

Local AI

MaskAgent can communicate with a locally running AI model through Ollama (e.g., DeepSeek-Coder). The AI runs locally instead of requiring the webpage context to be sent to a remote AI API.

Browser Agent

The agent can reason about the next browser action. Supported actions include: CLICK, TYPE, SCROLL, SELECT, DONE. The agent follows the user's requested objective and attempts to perform the required action on the webpage.

Requirements & Setup

Before running MaskAgent, make sure you have: A Chromium-based browser, Linux / Windows / macOS, Ollama installed, a compatible local AI model, and the MaskAgent source code.

1. Installing Ollama

Install Ollama on your system and verify it:

ollama --version

Check installed models:

ollama list

If the model is not installed, pull it:

ollama pull deepseek-coder

2. Configure Ollama for Browser Extension

Because MaskAgent is a browser extension communicating with a local Ollama server, the extension origin must be allowed. On Linux systems where Ollama runs as a systemd service:

sudo systemctl edit ollama.service

Add the following:

[Service]
Environment="OLLAMA_ORIGINS=chrome-extension://*"

Save and exit, then run:

sudo systemctl daemon-reload
sudo systemctl restart ollama

Verify the environment:

systemctl show ollama --property=Environment --no-pager

3. Test Ollama

First test the Ollama API:

curl http://localhost:11434/api/tags

Then test the model:

curl http://localhost:11434/api/generate \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-coder:latest",
    "prompt": "Say hello in one sentence.",
    "stream": false
  }'

4. Install MaskAgent in Chrome

  1. Open chrome://extensions
  2. Enable Developer mode
  3. Click Load unpacked
  4. Select the MaskAgent/ project folder
  5. MaskAgent should appear in your extension list. Enable it if necessary.

5. After Changing the Code

Whenever you modify the extension source code: Open chrome://extensions -> Find MaskAgent -> Click Reload -> Refresh the webpage -> Open MaskAgent -> Run Agent.

How MaskAgent Works

  1. User provides a task
  2. MaskAgent scans the webpage
  3. DOM/UI elements are identified
  4. Sensitive information is detected
  5. Sensitive information is masked
  6. Sanitized context is prepared
  7. Local Ollama model receives the context
  8. AI determines the next action
  9. MaskAgent validates the action
  10. Browser performs the action
  11. Page state is checked again
  12. Agent completes or continues the task

Security Considerations

⚠ Important: Do not test the extension with real passwords, banking information, credit/debit card numbers, government identification numbers, private documents, or confidential company information. Use synthetic test data during development.

MaskAgent is currently a research/development prototype. It should not be assumed that privacy detection is perfect. Potential limitations include:

  • PII detection may produce false positives or miss unusual formats.
  • Websites may dynamically modify their DOM.
  • Visual text can be difficult to identify accurately.
  • AI models can produce incorrect decisions.
  • Browser automation can perform unintended actions if not properly validated.
  • Local AI models may require significant CPU/RAM resources.
  • Passwords and sensitive fields require additional safeguards.

Design Philosophy

  1. Privacy First: Sensitive information should be protected before AI processing.
  2. Local Intelligence: When possible, AI inference should happen locally.
  3. Human Control: AI should assist the user rather than silently performing uncontrolled actions.
